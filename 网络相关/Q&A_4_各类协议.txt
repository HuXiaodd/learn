1.PPPoE
******************************************
PPPoE 报文头部（必须要记住的字段）
PPPoE 头长 6 字节，结构体定义必须加 packed：
Version / Type：各 4 bit，固定为 0x11。
Code：定义报文类型（PADI=0x09, PADO=0x07, PADR=0x19, PADS=0x65, PADT=0xa7）。
Session ID：发现阶段为 0x0000，Session 阶段由服务端分配。
Length：载荷（Payload）长度。
******************************************
PPPoE 状态机（发现阶段 Discovery Phase）
这是面试的高频考点，请按这个顺序记：
PADI (Init)：客户端广播。找“谁能给我提供服务？”
PADO (Offer)：服务端单播。多个服务端回复“我可以”。
PADR (Request)：客户端单播。选定一个服务端，“就选你了”。
PADS (Session-confirm)：服务端单播。分配 Session ID，握手成功。
PADT (Terminate)：任何时候一方想断开，发这个包。
面试话术：在我们的网关中，DPDK 程序会截获以太网类型为 0x8863（控制报文）和 0x8864（数据报文）的数据包进行分发处理。
************************************************
包结构:
Ethernet Header (14B)：
DMAC / SMAC
EtherType: 0x8863 (Discovery) 或 0x8864 (Session)。

PPPoE Header (6B)：
Ver(4bit) / Type(4bit): 0x11。
Code(1B): 标识报文类型（如 PADI=0x09）。
Session ID(2B): 发现阶段必为 0。
Length(2B): 后面 Payload 的长度。

Payload (PPPoE Tag)：
采用 TLV (Type-Length-Value) 格式。常见的有 Service-Name (0x0101) 和 Host-Uniq (0x0103，用于匹配请求和响应)。
**********************************************************
状态机与面试连环炮
PADI (广播) -> PADO (单播) -> PADR (单播) -> PADS (单播)。
面试题 1：如果 Session ID 在 PADS 之后变成了 0x0001，后续数据包怎么走？
答：后续所有数据包的 EtherType 变为 0x8864，且必须携带这个 Session ID。

面试题 2：PPPoE 为什么会导致 MTU 问题？
答：标准以太网 MTU 1500。PPPoE 头部占 6 字节，PPP 协议头占 2 字节，总共 8 字节。所以载荷 MTU 必须降到 1492，否则会触发 IP 分片，严重影响网关性能。

深度问题3:用户反馈拨号上网很慢，网页打不开，但 ping 大包能通，ping 小包也通。你怀疑是 MTU 问题，请结合 PPPoE 报文结构解释为什么？
现象解释：
以太网标准 MTU 是 1500。
PPPoE 因为多了 8 字节头部（6 字节 PPPoE + 2 字节 PPP），导致留给 IP 包的空间只有 1492。
深层原因（面试加分点）：
Ping 能通：是因为普通的 ping 包很小。如果你用 ping -l 1472（加上 IP 和 ICMP 头正好 1500），它就会失败。
网页打不开：网页走的是 TCP 协议。TCP 在握手时会协商 MSS。如果网关没有开启 MSS Clamping（MSS 钳制），服务器会认为能发 1460 字节的载荷（1460 + 20 IP + 20 TCP = 1500）。
结果：这个 1500 字节的包到了 PPPoE 网关后，因为加上 8 字节头变成了 1508，超过了物理网卡的限制。如果包设置了“不可分片（DF）”位，网关就会直接丢包。
解决方案：在网关上强行将经过的 TCP SYN 包里的 MSS 字段修改为 1452（1492 - 40）。
********************************************************************************
*** LCP (Link Control Protocol) 阶段
作用：建立、配置和测试数据链路。
关键点：协商 MRU (最大接收单元，类似 MTU)、魔术字 (用于检测环路)。
*** 认证阶段 (PAP/CHAP)
PAP：两次握手，明文传密码（极不安全，但简单）。
CHAP：三次握手，挑战/响应机制。服务端发随机数，客户端用密码做 MD5 混淆后发回。
面试点：在 500 万终端项目中，认证模块通常是独立的服务。网关需要把 PAP/CHAP 包剥离出来，转给后端的 AAA 认证服务器。
*** NCP (Network Control Protocol) 阶段
作用：针对不同的网络层协议进行协商。最常用的是 IPCP。
关键字段：客户端会在这里发一个请求，“给我分配一个 IP 地址吧”。服务端回 ACK 并带上分配的 IP。


2.DHCP
DHCP (IPv4) 的“四步走”
Discover (广播)：客户端找服务器。
Offer (单播/广播)：服务器提供 IP 及租期。
Request (广播)：客户端确认使用该 IP。
Ack (单播/广播)：服务器最终确认。
关键 Option 字段：
Option 53：消息类型（1-8）。
Option 54：Server Identifier（选定的服务器 IP）。
Option 51：IP 地址租期。
*********************************************************************
在 DHCP 流程中，为什么第三步 Request 还要发广播，而不是直接发给选定的服务器？
对于服务器来说4步完成才算完成,对于客户端来说,它可能有多个服务器,
广播是为了告诉其他落选的服务器释放该ip
*********************************************************************
xid (Transaction ID)：随机数，用于匹配请求和回复。
ciaddr (Client IP)：客户端已有的 IP（续约时用）。
yiaddr (Your IP)：服务器给客户端分配的 IP（Offer/Ack 里最关键）。
giaddr (Relay Agent IP)：如果跨网段，中继代理的地址。
chaddr (Client Hardware Addr)：客户端 MAC。
Magic Cookie: 固定为 0x63 0x82 0x53 0x63，它是 Option 字段的开始标志。
********************************************************************
DHCPv6 (IPv6)
DHCPv6 不再叫 Discover，而是叫 SARR 流程：
Solicit (寻找服务器)
Advertise (服务器宣告)
Request (请求参数)
Reply (最终答复)

关键术语：
IAID：接口关联标识符。
DHCPv6 彻底抛弃了广播，改用 组播 (Multicast)。
组播地址：ff02::1:2 (所有 DHCP 服务器/中继)。
DUID (Device Unique Identifier)：这是 IPv6 里的“身份证”，取代了单纯靠 MAC 地址识别设备的逻辑，支持多种生成方式（如基于时间、基于企业 ID）
****************************************************************************************
在 DPDK 中，如果你收到了一个 DHCP 数据包，你如何通过指针操作跳过以太网头、IP 头、UDP 头
，精准定位到 Magic Cookie 的位置？（提示：利用 rte_pktmbuf_mtod 和结构体偏移）：
DPDK 宏的使用：不要自己去算 data_buf + data_off，直接用 rte_pktmbuf_mtod(m, char *)，它返回的就是当前报文数据的起始地址。
DHCP 报文结构的特殊性：DHCP 的“头部”其实很大。在 UDP 之后，DHCP（基于 BOOTP）
有一个固定的 236 字节 的基本字段区（包含 op, htype, chaddr, sname, file 等）。
Magic Cookie 的位置：它紧跟在 236 字节的固定头之后。
修正后的代码逻辑（面试描述）：
“我会先通过 rte_pktmbuf_mtod 获取报文指针。然后根据层级偏移：以太网头（14B）+ IP 头（20B）+ UDP 头（8B）+ 
DHCP 固定头（236B）。偏移 278 字节 后，前 4 个字节就是 0x63 0x82 0x53 0x63（Magic Cookie）。”

中继和option82:
1. 为什么需要 DHCP Relay (中继)？
DHCP Discover 是广播包。广播不能跨路由器。
如果 500 万终端都在不同的子网，我不能给每个子网都配一个 DHCP 服务器。(vlan不同区分了不同的账号,每个账号子网相同)
解法：网关作为 Relay Agent，收到广播包后，把它封装成单播包，发给远端的 DHCP Server。

2. Option 82 (信息选项)
这是运营商定位用户的核心。它包含：
Circuit ID：用户在哪台接入交换机的哪个端口。
Remote ID：用户的身份标识（通常是 MAC）。
面试点：在网关开发中，我们需要解析并插入 Option 82，防止地址欺骗（即：A 用户不能用 B 用户的身份申请 IP）。

目标:搞清楚ospf,isis,bgp,vxlan,evpn
OSPF 是典型的链路状态路由协议，主要用于企业内网（IGP）
工作原理：
邻居发现：通过 Hello 报文互相认识。
同步 LSDB：大家交换 LSA（链路状态通告），直到每个路由器的数据库（LSDB）都一模一样。
计算路径：每个路由器以自己为根，利用 SPF (Dijkstra) 算法计算出一棵最短路径树。
DR/BDR:指定路由器,备份指定路由器
状态机:
| Down | 初始状态，还没收到 Hello 包。 | 无报文交互 |
| Init | 收到邻居的 Hello，但对方的邻居列表里还没我。 | Hello报文(Type 1) |
| 2-Way | 互相认识了，邻居关系建立完成（DR/BDR 选举在此阶段）。 | Hello报文(Type 1) |
| ExStart | 准备交换信息，确定主从关系（确定序列号）。 | Empty DBD (Type 2)报文 |
| Exchange | 交换 DD 报文，描述自己的数据库摘要。 | Summary DBD (Type 2)报文 |
| Loading | 发现对方有我没有的，发送 LSR 请求，对方回复 LSU。 | LSR / LSU / LSAck |
| Full | 数据库同步完成，邻接关系建立完成。 | Hello (维持) |

DD报文：DD 报文，全称是 Database Description Packet（在很多文档里也写作 DBD），中文叫 “数据库描述报文”，
它装的是本路由器数据库里所有 LSA 的 Header（头部信息），而不包含具体的路由路径、度量值等细节
--------------------------ospf通用报文头-----
一、 OSPF 公共报文头部 (24 Bytes)所有的 OSPF 报文开头都长一样，这是路由器的“初次见面礼”。
偏移 (Byte)          字段                    关键点
0                  Version                 ip版本 IPv4 是 2，IPv6 (OSPFv3) 是 3。
1                   Type                   包类型 1: Hello, 2: DBD, 3: LSR, 4: LSU, 5: LSAck。
2-3            Packet Length               包含头部的总长度。
4-7              Router ID                 路由器的“身份证号”，全网唯一。
8-11              Area ID                  区域 ID，骨干区域固定为 0.0.0.0。
12-13            Checksum                  标准校验和。

关于DR和BDR是什么---------并非是主机从机的主从,这对于一个网元的压力太大了.
answer:
你提到的“承担一个主机的责任”稍微有一点偏差。
真相：在以太网这种“大排档”环境（广播多路访问网络）里，如果每个人都和所有人交换路由，那场面就太乱了（复杂度是 $O(n^2)$）。
DR 的真实作用：它是**“信息同步中心”**。
所有“平民”路由器（DRother）只和 DR/BDR 建立全毗邻关系。
当某人链路变了，他只告诉班长（DR），班长再统一通知全班。
纠正：它不是承担主机的责任，而是承担**“公告栏管理员”**的责任，目的是为了减少网络中的协议报文流量。

报文头中描述的5种类型的报文信息主要目的:
1. Hello 报文 (Type 1) —— “交友申请”
Hello 报文里最重要的不是数据，是 Options（选项）字段：
E-bit (External)：是否允许外部 LSA（普通区域为 1，Stub 区域为 0）。quest:Stub区域是什么意思
N-bit (NSSA)：是否支持 NSSA 区域。quest:NSSA区域是什么意思
关键位：DR/BDR 优先级。如果优先级是 0，说明这台路由器甘愿当“平民”，不参与竞选班长（DR）。

answer:
Stub 区域（末梢区域）
直白解释：这是一个**“耳不听心不烦”**的区域。背景：互联网的外部路由（Type 5 LSA）成千上万。
如果某个小分支办公室的路由器内存很小（可能就是个 Zynq 的小核），它根本存不下全网路由。
做法：把这个区域配置为 Stub。区域边界路由器（ABR）会挡住所有从外面传进来的 Type 5 路由，然后只发给里面一个默认路由 ($0.0.0.0/0$)。
结果：里面的路由器只需要知道“出不去的包都扔给 ABR”就行了，内存占用瞬间从几百 MB 掉到几 KB。
说白了是为了屏蔽外部复杂的链路信息,而做的区域内节省内存的方法。
NSSA区域：
直白解释：这是一个**“想清静但又想开小灶”**的区域。
背景：NSSA 继承了 Stub 的特性（不接收外面的 Type 5），但它很特殊：这个区域连接了一个小型的外部网络（比如你司通过这个区域连了一个小客户的路由器）。
矛盾点：Stub 区域按规定是不准引入外部路由的，但你现在必须引入。
做法：发明了 Type 7 LSA。外部路由进 NSSA 时先伪装成 Type 7。等到这个路由通过 ABR 进入骨干网时，ABR 再把它变回正常的 Type 5。
口诀：对外不听（屏蔽 Type 5），对内自强（允许 Type 7）-----type7是NSSA区域特有的

2.DBD 报文 (Type 2) —— “家谱摘要”
在交换数据库阶段，DBD 报文有 3 个极其关键的 Flags（标志位）：

I (Init)：初始化位。如果是 1，表示这是发送的第一条 DBD。
M (More)：后续位。如果是 1，表示后面还有 DBD 报文。
MS (Master/Slave)：主备位。1 代表自己是 Master，0 是 Slave。

注意：这里的 Master/Slave 竞选不是看谁先发，而是看 Router ID，大的那个当 Master，负责控制序列号。

3. LSR (Link State Request) —— Type 3 “补货清单”
场景：在你和邻居交换完 DBD（家谱摘要） 后，对端数据比自己的数据更新更多,于是发送的更新请求
它的作用：向邻居请求具体的 LSA 详细信息。
报文内容：它不含具体的路由细节，只包含它想要的 LSA 的三元组（Type, ID, Advertising Router）。
通俗比喻：就像你看了对方的菜单（DBD），然后指着其中两道菜说：“这两道我没吃过，请给我详细介绍一下做法（LSU）。”
状态机位置：发完 LSR，路由器就进入了 Loading（加载） 状态。

4. LSU(Link State Update) 报文 (Type 4)
LSU 是 OSPF 最重头的报文，因为它包含了真正的 LSA (Link State Advertisement)。

5.LSAck (Link State Acknowledgment) —— Type 5 “收条/确认函”
场景：OSPF 不像 UDP 那样发完就管，它要求**“事事有回音”**。当你收到邻居发来的 LSU（真正的路由货品） 时，你必须给人家一个交代。

它的作用：确认已经收到了一条或多条 LSA。
报文内容：它非常精简，只包含被确认的那些 LSA 的 20 字节头部。
为什么要发头部？ 因为不需要发完整的信息,头部信息足已确认
重要特性：为了节省带宽，OSPF 允许“延迟确认”。即收到多个 LSU 后，打包成一个 LSAck 发回去。

报文交互的实际数据是lsa,他的关键信息：
LSA 头部：路由信息的“DNA”
每一条路由信息（LSA）都有一个 20 字节的头部：

LS Age：存活时间。每经过一个路由器加 1 秒，到 3600 秒（1 小时）还没更新就“死亡”。
Options：同 Hello 报文。

LS Type：最关键的一个字节。
Type 1 (Router)：每个路由器都会发的，描述自己的接口状态。
Type 2 (Network)：由 DR 发送，描述这个网段里有哪些人。
Type 5 (AS-External)：描述如何去往公司外部（互联网）。quest:as-external这不是域(as)扩展吗,应该是自治域外网络吧

Link State ID：路由的目的网络地址。
Advertising Router：谁发出的这条路由。
LS Sequence Number：版本号。每次链路变动，这个数字就 +1。路由器只相信数字更大的（更新的）信息。

ISIS协议：
OSPF：生来就是为 IP 服务的，报文必须封装在 IP 头后面。
IS-IS：生来是为了 OSI 模型（CLNS）服务的。它把 IP 看作是它的一个“插件”。
优势：由于不依赖 IP，即便接口没有 IP 地址，IS-IS 邻居也能建立。同时，它对各种新协议（如 IPv6、Segment Routing）的兼容性极强，只需要加个“插件包”就行。

级别                对应角色                    作用
Level-1 (L1)        区域内路由器                只负责本区域内的路由同步，类似于 OSPF 的非骨干区域。
Level-2 (L2)        骨干路由器                  负责区域间的路由传递，是整个网络的骨架（Area 0）。
L1/L2               区域边界                    相当于 OSPF 的 ABR。它同时维护两个数据库。

报文类型：PDU (Protocol Data Unit)
PDU 类型                 全称,                    对应 OSPF 报文                          作用
IIH                     IS-IS Hello              Hello                             发现邻居、维持关系。
LSP                     Link State PDU           LSU                               核心！ 承载真正的链路状态信息。
CSNP                    Complete SNP             DBD (摘要)                        描述整个数据库的目录。广播网中由“班长”定期发。
PSNP                    Partial SNP              LSR / LSAck                       部分摘要。用于“求货”或“确认收货”。

IS-IS 的数据段是由无数个 TLV 模块 拼成的。
tlv的好处
T (Type)：告诉程序这是什么数据（比如：22 代表邻居信息，128 代表 IP 路由）。
L (Length)：这一段数据有多长。
V (Value)：具体的内容。

为什么这么设计------避免重构协议头
OSPF 可能要重构协议头；
IS-IS 只需要定义一个新的 Type 数值，老路由器不认识就直接跳过（根据 Length），新路由器就能解析。
这就是为什么 Segment Routing (SRv6) 首选 IS-IS 的原因。

1. Hello 报文：IIH (IS-to-IS Hello)
作用：建立和维持邻居关系。就像在说：“嘿，我是 System ID 为 XXX 的路由器，我在 L1 区域。”
L1 LAN IIH (Type 15)：用于广播网（如以太网）的 Level-1 邻居。
L2 LAN IIH (Type 16)：用于广播网的 Level-2 邻居。
P2P IIH (Type 17)：用于点对点链路（不分 L1/L2，都在这一个类型里协商）。
关键字节：
Circuit Type：1 表示 L1，2 表示 L2，3 表示 L1/L2。
System ID：发送者的 6 字节唯一标识。
Holding Time：如果这么长时间没收到我的 Hello，就当我已经“挂了”。

2. 链路状态报文：LSP (Link State PDU)
作用：核心干货。承载了所有的路由信息（邻居是谁、网段是多少、Metric 是多少）。
L1 LSP (Type 18)：Level-1 的路由信息。
L2 LSP (Type 20)：Level-2 的路由信息。
关键字节：
LSP ID：由 System ID + 伪节点 ID + 分片号组成。
Sequence Number：4 字节序列号。越大说明信息越新。
Remaining Lifetime：老化时间，从 1200 秒倒计时到 0。
ATT (Attached bit)：L1/L2 路由器用来告诉 L1 路由器：“我有去往骨干网的门，跟我走！”

3. 完全序列号报文：CSNP (Complete SNP)
作用：“全家谱目录”。包含数据库中所有 LSP 的摘要（LSP ID、序列号、校验和）。

1. 广播网 (LAN) 模式 —— 
在以太网里，为了省事，大家不私下交易，靠DIS规划。
建立 Up 后：所有路由器立刻向组播地址发送自己的 LSP（我的路由信息）。
DIS 的动作：DIS 收集所有人的 LSP，汇总成一个大目录 CSNP，然后每隔 10 秒往全班广播一次。
平民的动作：
如果你发现 DIS 的目录里有你没有的 LSP → 发送 PSNP (求货单) 请求。
如果你发现你有但是 DIS 目录里没有的（或者你更新） → 直接发送 LSP 顶替掉旧的。
注意：广播网里没有“收条”，因为 DIS 循环广播目录本身就是一种“确认”。

2. 点对点 (P2P) 模式 —— “私下确认制”
在 P2P 链路上，没有DIS，大家必须“双向确认”。
建立 Up 后：双方立刻互发一次 CSNP（目录）。
求货：发现对方有自己没有的，发送 PSNP 请求。
确认：这是关键！ 当 A 给 B 发送了一个具体的 LSP，B 必须回复一个 PSNP 作为“收条（Ack）”。如果 A 没收到这个 PSNP，会一直重传那个 LSP。

BGP 的 4 种报文类型
BGP 的报文结构非常固定，开头都有一个 16 字节的全 1 标记（Marker）用来同步。
    Open (Type 1)：
    作用：建立邻居。包含：BGP 版本、自己的 AS 号、Hold Time、BGP Identifier（类似 Router ID）。

    Update (Type 2)：
    作用：最核心报文。里面塞满了路由信息。
    包含：撤销路由列表（我不用的路）、路径属性（AS-Path 等）、可达路由前缀（NLRI）。

    Keepalive (Type 3)：
    作用：续命。默认 60 秒发一次。如果 180 秒没收到，邻居直接断开。

    Notification (Type 4)：
    作用：报错。一旦发现不对劲（比如 AS 号配错了），发完这个包立刻断开连接。

BGP 的路径属性 (Path Attributes)

AS-Path：记录这条路由经过了哪些 AS。
防环路：如果你收到的路由里有自己的 AS 号，直接扔掉。
选路：经过的 AS 越少，路径通常越优。
Next Hop：下一跳是谁。
Local Preference：告诉家里人，出家门走哪条路更好（控制流出）。
MED (Multi-Exit Discriminator)：告诉邻居，进我家门走哪个口（控制流入）。

isis,ospf与bgp的区别和关系：ospf和isis是as内交换路由,bgp是as间交换路由。
对于这个关系要说到IGP(Interior Gateway Protocol - 内部网关协议)和EGP(Exterior Gateway Protocol - 外部网关协议).

IGP (Interior Gateway Protocol - 内部网关协议)：
代表：OSPF、IS-IS。
范围：在一个 AS内部运行。
核心目标：速度。它们追求以最快的速度算出一张全图，让包在AS内跑得最顺溜。

EGP (Exterior Gateway Protocol - 外部网关协议)：
代表：BGP（目前互联网上唯一的 EGP）。
范围：在 AS 与 AS 之间运行。
核心目标：控制与策略。它不关心路径是不是最短，它关心的是“这跳路费贵不贵”、“走这路安不安全”。
两者缺一不可,就像是网关只用关心子网,和一个小网段一样
如果只用BGP 的话：BGP 建立在 TCP 之上，收敛速度（发现路断了到重新选好路的时间）按分钟计。而 OSPF/IS-IS 可以在几百毫秒内完成。
如果只用OSPF 的话：OSPF 要求每个交换机手里都有一张全邻居路由。如果把整个互联网 100 多万条路由全塞进 OSPF，路由器的 CPU 会直接烧掉。

EVPN其实是隶属于BGP下的一个协议族

BGP 有一个天生的优势：扩展性极强。
以前的 BGP 只会传 IPv4 路由（“去这个 IP 走哪”）。
后来有了 MP-BGP（多协议 BGP），它变得像个万能插件架，可以传 IPv6、传 VPNv4。
现在，大家给 BGP 增加了一种新的插件，叫 EVPN (AFI=25, SAFI=70)。有了它，BGP 就可以传 MAC 地址 和 终端 IP 了。

2. EVPN 到底在 BGP 里传什么？
TCP端口 179
EVPN 定义了几种专用的“路由类型”（Route Types），这就像是不同格式的快递单：
Type 2（MAC/IP 路由）：最常用！ 告诉全网：“MAC 地址 A 挂在我这个 VTEP 下面，对应的内层 IP 是 X”。
Type 3（网通路由）：用来建立隧道，处理 BUM（广播、组播、未知单播）流量。
Type 5（前缀路由）：用来传网段信息，实现不同 VNI 之间的三层互通。

quest:bgp不是已经打通as间的路了吗,为什么还需要evpn去搭桥多此一举?
answer:bgp解决了两个as打通的问题.
evpn解决了两个as间两个设备想用同一个ip且不冲突的问题 比如说as1里的mac-a ip-1想和as2里的mac-b ip-1交互的问题.

Type 2 到底是什么？（MAC/IP 路由）
在你刚才说的那个 255 台手机的场景里，Type 2 路由的作用就是**“户口登记”**。
它的内容：它告诉全网，“手机 A（MAC-A, IP-1.5）在交换机 1 后面，请封进 VNI 1000”。
它的角色：它是 BGP 报文里的一个信息条目。

在 EVPN 里，真正负责“打通隧道”的消息其实是 Type 3 路由 (Inclusive Multicast Route)：
Type 3 的任务：它是交换机之间互打招呼

在 BGP EVPN 中，如果你听到有人聊 UMR，他其实是在聊 BUM 流量（Broadcast 广播, Unknown-unicast 未知单播, Multicast 组播）的处理规则。

逻辑：
Type 2 是精准导航。(mac/ip)
UMR/Type 3 是“广播寻人”。
作用：当你的交换机收到一个包，但在 EVPN 表里查不到目的地（比如一个新的手机刚插上，还没来得及发 Type 2 报文），交换机不能直接丢包啊！
它会根据 UMR (Unknown Multicast Route) 规则，把这个包复制一份，发给所有建立过隧道的邻居
