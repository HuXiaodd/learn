1.红黑树和b+树有什么区别,其实我不太清楚什么是b+树
答:
红黑树----------
每个节点要么是红的，要么是黑的。
根节点是黑的。
每个叶子节点（NIL）是黑的。
如果一个节点是红的，则它的两个子节点都是黑的（不能有连续的红节点）。
从任一节点到其每个叶子的所有路径包含相同数目的黑色节点（黑高平衡）。
左旋/右旋：这是为了在插入/删除导致失衡时，重新调整树结构。
b+树------------
多路平衡：一个节点不只有两个子节点，可能有几百个。
叶子节点存数据：非叶子节点只存索引，所有真实数据都存在最底层的叶子节点。
叶子相连：所有的叶子节点用指针连成一个双向链表，非常适合范围查询（比如：查找 ID 从 10 到 100 的所有终端）

2.我不清楚你说的cache 是什么？ 是比如 cpu的一级/二级缓冲吗？如果是的话,
对于cpu的话处理数据是不是让他尽量处理同一个数据会更有效率?(因为在同一个缓冲?cache miss的概率更小?)
同时cache line是什么意思,你的意思难道是所有的cpu共用同一块cache吗,那cache的"最小单位"是这个cache line吗？
答:
Q：所有的 CPU 共用同一块 Cache 吗？
不完全是。现在的多核 CPU 架构通常是：
L1/L2 Cache：每个核心（Core）独立拥有。
L3 Cache：所有核心共享。
结论：核心之间竞争最激烈的是 L3 和内存带宽。
没错，它就是 CPU 内部的 L1/L2/L3 缓存。
Q：处理同一个数据更有效率吗？
是的。这叫 时间局部性（Temporal Locality）。如果一个数据被访问，它很可能很快再次被访问。放在 Cache 里，CPU 就不用去慢吞吞的内存（RAM）里取了。
面试杀手锏：在发包程序中，我们要尽量保证一个报文（mbuf）的整个处理流程由同一个物理核完成。如果报文从核 0 传给核 1 处理，核 1 的 Cache 里没有这
个 mbuf 的数据，就会发生 Cache Miss，性能瞬间下降。

3.对于伪共享,我有问题,这个伪共享他针对的是否是l3缓冲?因为l2l1的每个cpu都独有缓冲,并不会伪共享吧？
答：错误,恰恰l1和l2才会发生伪共享
硬件逻辑：虽然 L1/L2 是私有的，但 CPU 必须保证所有核心看到的内存数据是一致的 。如果核 0 修改了它 L1 里的一个字节，核 1 的 L1 里如果也有这块数据的副本
，就必须被强行失效 。MESI 协议：当核 0 修改 Cache Line 中的变量 A，硬件会发送信号给总线 。核 1 发现自己的 L1 缓存里也有这个 Cache Line（即使它只想访
问变量 B），它的这行缓存也会被标记为 Invalid（无效） 。
结论：伪共享的痛苦在于，明明是私有缓存，却因为物理上相邻的数据（在同一个 64 字节的 Cache Line 内）被其他核修改，导致自己的私有缓存频繁“报废”，
必须重新从 L3 或内存拉取数据

对问题3的答复我依然有一个设想:其实,l2和l1,它记录的是内存的地址?(内存的指针?),当"指针"所指的值被改变,那另一个核心所读
的值应该被改变了吧?我相信内核不会去做把内存存储的值拷贝到不同cpu的cache里,然后一个改动了另一个也要跟着改这种低效操作吧?
答:
事实恰恰相反：Cache 里存的真的是“数据的副本（值）”，而不是指针。
为什么不存指针？ 如果 Cache 只是存了内存地址，那么 CPU 每次想看数据时，依然要顺着地址去访问内存。内存的访问延迟大约是 100-300 个时钟周期，而 L1 只需要 3-4 个周期。如果去内存取值，Cache 就失去了“高速”的意义。
物理实现： 当 CPU 执行读取指令时，硬件会自动将内存中以该地址为起始的 64 字节（Cache Line） 完整地拷贝到 CPU 内部的 SRAM（静态随机存取存储器）中 。
关于“低效”的辩证： 虽然“同步不同核心的副本”看起来很麻烦，但相比“每次都去内存读数据”，这种麻烦是极其划算的。缓存一致性协议（MESI） 就是为了在享受 Cache 高速的同时，通过硬件电信号自动处理这些副本的同步问题，
不需要内核（软件层）干预。

rte_prefetch0:指令预取,把内存中的空间预取到缓冲中.

内存屏障（Memory Barrier）到底是干嘛的？
你要先接受一个扎心的事实：现代 CPU 和编译器都是“不诚实”的。
为了性能，它们会进行乱序执行（Out-of-Order Execution）。
编译器优化：觉得代码里先写 A 再写 B 不顺手，调换顺序。
CPU 优化：觉得写数据到内存太慢，先存在一个 Store Buffer 里，结果后写的指令可能先到达了内存。

内存屏障的作用：它就像一道**“防火墙”或“哨兵”。它告诉 CPU 和编译器：“在屏障之前的指令没干完之前，绝对不准跳过去执行屏障之后的指令


pmd和传统驱动的区别
传统驱动（中断模式）：就像你在家等外卖，外卖员到了敲门（中断），你才放下手里的活去开门。如果外卖很多，你就要不停地开门关门，累死在门口。
PMD 模式（轮询模式）：就像你直接站在家门口，眼睛死死盯着路口，只要外卖员一露头，你直接抢过来就跑。你不需要等别人敲门，你一直在主动观察。
在代码里：PMD 就是一个死循环（while(1)），它不停地去读取网卡的硬件寄存器，看看有没有新的描述符（新包）传过来。


cpu亲和性:
在Linux内核中，所有的线程都有一个相关的数据结构，称为task_struct。这个结构非常重要，原因有很多；
其中与亲和性相关度最高的是cpus_allowed位掩码。这个位掩码由n位组成，与系统中的n个逻辑处理器一一对应。
具有4个物理CPU的系统可以有4位。如果这些CPU都启用了超线程，那么这个系统就有一个8位的位掩码。
如果针对某个线程设置了指定的位，那么这个线程就可以在相关的CPU上运行。
因此，如果一个线程可以在任何CPU上运行，并且能够根据需要在处理器之间进行迁移，
那么位掩码就全是1。实际上，在Linux中，这就是线程的默认状态。
Linux内核API提供了一些方法，让用户可以修改位掩码或查看当前
的位掩码：
·sched_set_affinity（）（用来修改位掩码）
·sched_get_affinity（）（用来查看当前的位掩码）
注意，cpu_affinity会被传递给子线程，因此应该适当地调用
