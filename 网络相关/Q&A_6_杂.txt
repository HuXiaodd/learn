ring的多生产者多消费者,多生产者单消费者模型
场景 A（MPSC）：多个网卡队列（由多个核心读取）的数据，需要汇总到一个核心进行处理。
例如，你有 8 个网卡队列（8 个核心在读），但你只需要 1 个核心来处理所有数据包。
这时，8 个生产者（读取队列的核心）向同一个 rte_ring 写入数据，1 个消费者
（处理核心）从中读取。这就是“多生产者/单消费者”（MPSC）模型。
场景 B（MPMC）：多个处理核心需要同时从同一个队列中获取数据进行并行处理。
例如，你有一个队列的数据包需要进行加密，你希望用 4 个核心同时处理。
这时，4 个消费者会竞争从同一个 rte_ring 中读取数据。这就是“多生产者/多消费者”（MPMC）模型。


tcp流的流量控制
目的是防止快发送方给慢接收方发数据造成接收缓冲区溢出的崩溃
接收方根据缓存大小确定接收窗口大小，并通知发送方；发送方保证发送窗口小于接收窗口大小
接收窗口大小：保持最后收到字节 - 最后读出字节 ＜ 缓冲区长度，即 接收窗口 = 缓冲区长度 - 已确认未读出长度
（最后一个连续已确认字节序号 - 最后一个已读出字节序号）

对于网元,无法对tcp流的流量控制进行干扰，但是还是有一些处理办法的
处理方法————————————————
拥塞避免：通过监视网络资源使用情况，在拥塞发生前主动采取措施
尾部丢弃(Tail Drop)：当队列长度达到上限时丢弃新到达的数据包，防止缓冲区溢出
加权随机早期检测(WRED)：在队列长度达到阈值前就开始随机丢弃数据包，避免TCP全局同步现象
拥塞管理：在拥塞已发生时，通过调整报文调度次序确保关键业务优先处理
优先队列(PQ)：按优先级顺序调度，高优先级业务先处理
加权轮询(WRR)：按权重分配带宽，保证各业务公平使用资源
加权赤字轮询(WDRR)：基于报文长度进行调度，更精确地控制带宽分配

DMA（Direct Memory Access，直接内存访问）是一种硬件机制，允许外设（如网卡、磁盘驱动器、ADC等）与系统内存之间直接传输数据，无需CPU全程参与。
它通过DMA控制器（DMAC）实现，这是一个专门的硬件组件，通常集成在芯片组或SoC中。
2. DMA的核心作用
减轻CPU负担：将CPU从繁琐的数据搬运工作中解放出来，使其能专注于逻辑控制和算法运算。
提高数据传输效率：实现高速数据传输，尤其适合处理大量数据的场景。
降低系统延迟：避免因CPU忙于其他任务而导致数据丢失（如ADC采样中的Overrun）。
降低功耗：CPU可在DMA工作时进入低功耗模式，仅在传输完成时被唤醒。
3. DMA的工作原理
DMA的工作过程可分为四个阶段：
DMA请求：外设向DMA控制器发送请求信号
DMA响应：DMA控制器接管总线控制权
数据传输：DMA控制器直接在设备和内存之间搬运数据
传输结束：DMA控制器向CPU发送中断，交还总线控制权


dpdk的处理和初始化流程:
1. 初始化阶段
环境准备：
加载UIO驱动（如igb_uio.ko），将网卡从内核驱动解绑
通过rte_eal_init()初始化EAL环境，配置大页内存
描述符环创建：
调用rte_eth_rx_queue_setup()为每个RX队列分配：
rx_ring：硬件描述符环，存储描述符（含物理地址）
sw_ring：软件环，存储对应mbuf的虚拟地址指针
驱动从内存池(rte_mempool)中预分配mbuf，填充描述符
网卡配置：
设置网卡的接收/发送描述符数量（如40G网卡通常配置2048个收包描述符）
配置RSS（接收端缩放）实现多队列负载均衡

2. 数据包接收流程（RX）
网卡收包：
数据包到达网卡，暂存于RX_FIFO缓冲区
网卡DMA引擎从rx_ring获取可用描述符，读取其中的物理地址
通过PCIe总线，不经过CPU，直接将数据包写入mbuf数据缓冲区
状态更新：
DMA写入完成后，网卡回写描述符，更新状态信息
将DD位置为1，表示数据包已就绪，所有权归还给驱动
应用轮询：
应用调用rte_eth_rx_burst()，检查rx_ring中DD位为1的描述符
从sw_ring获取对应mbuf指针，更新mbuf元数据（包长度、端口等）
将mbuf传递给上层应用处理
资源回收：
驱动为已处理的描述符重新分配新的空mbuf
将描述符状态位清零，移交给网卡用于接收新数据包

3. 数据包发送流程（TX）
应用准备：
应用将待发送数据包的mbuf指针传入rte_eth_tx_burst()
PMD驱动将mbuf数据缓冲区的物理地址填入TX描述符
网卡发送：
网卡DMA引擎从TX描述符环读取描述符
根据描述符中的物理地址，从mbuf数据缓冲区读取数据包
通过PCIe总线将数据包发送到网络
状态确认：
发送完成后，网卡回写描述符，更新状态位
应用通过轮询确认发送完成，回收mbuf内存

DPDK 并不试图统一“硬件环”的格式，它只统一“软件接口”的结果.
1. 物理上的隔离：一端口一驱动你担心的“放在一个环上无法辨别”的情况在物理上是不存在的 。
每个物理网口（Port）在初始化时，都会根据其硬件型号加载特定的 PMD（轮询模式驱动） 。
如果你有两块网卡（一块 Intel ixgbe，一块 Intel i40e），它们拥有各自独立的硬件环（Hardware Ring）内存空间 。
ixgbe 的驱动代码只看 ixgbe 的环，i40e 的驱动只看 i40e 的环 。它们绝不会混在一起。
*所有的硬件,其实都有他自己的驱动,这个初始化在eal_init的时候会根据不同的设备加载不同的驱动,对上层来说,接口相同,但是函数指针指向不同的设备。

2. 逻辑上的多态：函数指针的妙用DPDK 应用层调用 rte_eth_rx_burst(port_id, ...) 时，这其实是一个统一的入口 。
在内核内部，port_id 对应一个 struct rte_eth_dev 结构体，里面有一个函数指针 rx_pkt_burst 。
ixgbe 网口：该指针指向 ixgbe_recv_pkts，它内部写死了处理 ixgbe_adv_rx_desc 的逻辑 。
i40e 网口：该指针指向 i40e_recv_pkts，它处理的是 i40e 专有的描述符格式 。

DPDK 的逻辑是：先把坑挖好，把地址告诉网卡，包来了直接填坑。
在网卡驱动初始化的时候，会有两个并行的“环形阵列”：
Hardware Ring (硬件环)：给网卡看的，里面只存物理地址 (IOVA)。
Software Ring (软件环)：给 CPU 看的，里面只存 struct rte_mbuf * 指针。
这两个环的下标（Index）是完全对应的。

1. 填坑阶段（驱动初始化或补包时）
CPU 会从 Mempool 里取出一个 mbuf。
它计算出这个 mbuf->data 区域的物理地址。
它把这个物理地址填进 Hardware Ring 的第 5 个格子。
它把这个 mbuf 的虚拟地址指针填进 Software Ring 的第 5 个格子。
此时，第 5 个坑位已经和这个具体的 mbuf 绑定了。

2. 搬运阶段（DMA 运作）
包从网线进来了。网卡看了一眼 Hardware Ring 的第 5 个格子：
“哦，物理地址是 0x12345600，搬运工（DMA）出发！”
DMA 直接把报文数据写到了 0x12345600。
注意：这个地址正好就是那个 mbuf 的数据区。数据此时已经躺在 mbuf 里了，根本不需要二次拷贝。

3. 收割阶段（CPU 轮询）
你的代码调用 rte_eth_rx_burst：
CPU 轮询 Hardware Ring，发现第 5 个格子的 DD 位（Done）变 1 了。
CPU 直接去 Software Ring 的第 5 个格子取回 struct rte_mbuf * 指针。
瞬间完成：CPU 拿到了指针，指针指向的内存里已经有了数据。

关于存储结构的树：
B-Tree(自平衡树),LSM-Tree（日志覆盖树）
| 特性 | B-Tree (如 MySQL InnoDB) | LSM-Tree (如 LevelDB, RocksDB) |
| :--- | :--- | :--- |
| 写入性能 | 较慢 (随机写，涉及页分裂) | 极快 (顺序写，追加日志) |
| 读取性能 | 稳定且快 (树高低，I/O少) | 稍慢 (需查多处，有读放大) |
| 磁盘空间 | 利用率高，碎片少 | 需要额外空间进行合并 (写放大) |
| 典型应用 | 传统关系型数据库、强事务系统 | 大数据存储、日志系统、NoSQL |

布隆过滤器:在代码优化中的快慢路径决策器,把账号开通的快速业务流程(直接转发---百分之99的包都是转发,丢包)作为哈希,让业务更快.

1.B树
叶子节点独立：各叶子节点之间没有连接
查询路径：查找时需要从根节点逐层定位，无法直接在叶子层横向移动
2. B+树
叶子节点形成链表：所有叶子节点通过指针连接成有序链表（通常是双向链表）
查询路径：找到一个叶子节点后，可以沿链表顺序访问其他叶子节点。

B-Tree树的分裂:b_tree 是以页为每个树的结构单位,一页包含最多m-1(m为分支因子)个分隔符(区间标记)用以区分不同的区间(区间数量为分隔符+1即为m格),
	但是叶子的话,它只有数据,根本不需要子页,所以它有m-1个数据.当叶子节点满了以后,叶子节点会分裂,中间节点上移(父节点如果也满则递归上移).
B+-Tree树的分裂:中间关键字保留在原节点中，仅将其副本插入父节点,优先尝试向兄弟节点"借空间"，而不是立即分裂,分裂后，原节点和新节点通过链表连接，
	保持叶子节点的有序性,内部节点分裂时，中间关键字会被移动到父节点（与B树相同）
